## C. 同名模块消歧 + ffmpeg 封装合并（同日第二轮）

先澄清一个判断：5 组同名里 **4 组是「同名不同责」，不是重复实现**。真正重复的只有 ffmpeg 薄封装。

### 重命名（消歧，不改行为）

| 旧路径 | 新路径 | 理由 |
|---|---|---|
| `backend/ffmpeg_executor.py` | `backend/executor.py` | 它是执行 `FFmpegCommand` 的高阶执行器（重试/取消/进度），与 media 的薄封装区分 |
| `runtime/task_queue.py` | `runtime/render_task_queue.py` | 类本来就叫 `RenderTaskQueue`；与 `agent/core/task_queue.py`（Agent 任务）区分 |
| `runtime/scheduler.py` | `runtime/distributed_scheduler.py` | 类 `DistributedScheduler`；与 `thinking/scheduler.py`（增量重算）区分 |
| `core/graph_pipeline.py` | `core/langgraph_pipeline.py` | 这是 LangGraph 版本；`engine/bridge/graph_pipeline.py` 是 Remotion 版本 |
| `core/material_api.py` | `core/material_providers.py` | 它是 Pexels/Pixabay 素材源客户端，不是 HTTP 路由 |

同步更新 9 个文件的 import / 文档字符串，旧模块名零残留。

### 真重复合并：ffmpeg 薄封装

`media/ffmpeg_executor.py`（120 行：`run_ffmpeg` / `run_ffprobe` / `get_video_duration`）
与 `core/utils/ffmpeg_runner.py`（已有 `run_ffmpeg` / `run_ffmpeg_safe`）职责重叠：

- `get_video_duration` 合入 `core/utils/ffmpeg_runner.py`，全项目只保留这一处 ffprobe 封装
- `media/concat_renderer.py` 改用 core 版本；`run_ffmpeg` 语义从「返回 result 对象」改为
  「失败抛 RuntimeError」，调用处改为 try/except 并保留原错误信息截断
- 删除 `media/ffmpeg_executor.py`

### 顺带修复

`runtime/worker_server.py` 的渲染计时从 `time.monotonic()` 改为 `time.perf_counter()`：
Windows 时钟粒度约 15ms，毫秒级渲染会被记成 `0.0s`，导致 `test_render_success` 偶发失败。

### 验证

```

tests/test_worker_server.py → 连跑 3 次均 13 passed
```

### 已知（非本轮引入）

`core/langgraph_pipeline.py` 依赖 `langgraph`，requirements 里有声明但当前 venv 未安装，
导入会失败；该模块只被 `agent/mcp/server.py` 的工具函数惰性调用，重命名前行为一致。
