### 复盘：时间轴编辑器已移除（同日）

上面的时间轴做完后复盘，判断方向错了：

- **产品层面**：用户用这套系统买的是"少做决定"。帧级/轨道级手动编辑是剪映的强项，
  搬进来等于把最该省掉的人工又还给用户。
- **抽象层面**：轨道按"模块"切、起止时间从音频反推，表达不了"第 3 句字幕早了 200ms"
  这类真实需求；而且 `render()` 根本不读它。
- **重复造轮子**：智能导演页已有更正确的形态 ——「改第 3 句 / 删第 5 句 / 加一句」，
  背后是 `intent_parser` + patch + 局部重生成。

处理：删除导航入口、`🎞️ 时间轴` 页、相关前端 JS、`thinking/timeline_builder.py`
及其测试；`api/timeline_api.py` 恢复到改造前（模块保留、仍挂载，但不再有前端入口）。

保留的经验：**"能编辑"不等于"该编辑"**。后续若要提升可控性，应做成意图级/参数级
（时长目标、语速、节奏模板、重做某一段），而不是时间轴。

## AI 动效：零图像 API 的动态画面（同日）

**动机**：没有生图/生视频预算时，只要有一个文本 LLM，就应该能做出动态画面。

**链路**：文本 LLM 写单文件 HTML（内联 CSS/SVG + `@keyframes`）→ Playwright 逐帧截图
→ ffmpeg 编码 MP4。全程本地，成本 = 一次文本补全。

### 实现

- `services/html_motion/prompts.py`：硬约束提示词（单文档、无 script/外链、纯 CSS 动画、
  总时长、字号、节拍）
- `services/html_motion/generator.py`：
  - `extract_html`：兼容代码围栏 / 裸文档
  - `sanitize_html`：去 `<script>`/`<iframe>`/`<link>`/`@import`/内联事件
  - 内置 `DEMO_HTML`（不调用任何 API 的示例）
  - **踩坑**：`get_llm_client()` 返回的 `DualModeLLMClient` 只有 `chat()`，没有 `generate()`；
    已改为优先 `chat(messages)`，兼容只有 `generate()` 的实现
- `services/html_motion/renderer.py`：
  - `document.getAnimations()` 全部 `pause()`，逐帧设 `currentTime` —— CSS 动画可精确寻址
  - 阻断外部请求，避免模型写的外链拖慢或污染渲染
  - **性能**：1080×1920 的 PNG 截图约 438ms/帧，JPEG(q92) 只要 56ms/帧；
    5s@24fps 从 46s 降到 11s
- `api/html_motion_api.py`：`/presets`、`/generate`、`/render`（后两者 SSE）
- 前端 `✨ AI 动效` 页：主题 + 风格 + 时长/帧率，内置示例、HTML 可编辑后重渲
